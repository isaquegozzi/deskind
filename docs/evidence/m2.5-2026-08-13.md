# Evidência M2.5 — USB/ADB — 2026-08-13

## Ambiente físico

- tablet: Samsung SM-X400, serial ADB `RX2Y9004VHF`;
- dispositivo de input: `sec_e-pen`;
- transporte: cabo USB com dois `adb reverse` TCP;
- control: `127.0.0.1:27183`;
- input: `127.0.0.1:27184`;
- receiver: DeskInk Windows Host .NET 10.

## Implementação validada

- `HELLO`/`HELLO_ACK` no canal de controle;
- `INPUT_BIND` com session ID aleatório e token de 16 bytes;
- framing TCP little-endian com leitura exata e limites antes de alocar;
- conexão input separada do controle e `TCP_NODELAY`;
- captura de history antes da amostra atual, por pointer ID/tool;
- batches com no máximo 32 samples;
- fila de envio limitada: MOVE substituível, transições DOWN/UP/CANCEL preservadas;
- receiver valida sessão, sequência e frames antes da state machine;
- fechamento da conexão chama `ReleaseAll()`.

## Perda e recuperação

O cabo foi removido fisicamente enquanto o último estado recebido era `Contact`.
O receiver registrou:

```text
INPUT CLOSED session=FDB08ECCA38E87A9 frames=1631 samples=13144 release=Up
```

Após reconectar o cabo, o device voltou autorizado com novo `transport_id`, os
dois reverses foram reaplicados e o botão `Connect USB` criou uma nova sessão:

```text
CONTROL READY session=BFB03632B4F21F59
INPUT READY session=BFB03632B4F21F59
```

Uma terceira sessão foi usada para instrumentar os ranges físicos, também sem
gap, duplicata, reorder ou drop.
